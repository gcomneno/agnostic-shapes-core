# PETRA path interpretation

Status: non-normative research theory.

This note connects PETRA interpretation theory with the existing theory of
finite witnessed ADD/REMOVE paths.

It does not modify the ASHES/SHAPES carrier, structural equality, elementary
edit legality, runtime behavior, serialization, or the normative PETRA
interpretation specification.

## 1. Structural basis

Let `C` denote the free path category generated by witnessed elementary
ADD/REMOVE edits.

Its objects are ASHES forms.

Its arrows are finite composable witnessed edit paths.

For every form `S`, the empty path is `id_S`.

Path concatenation is associative.

Distinct paths with equal source and target are not identified merely because
their endpoints agree.

## 2. State interpretation versus path interpretation

A state interpretation assigns mathematical meaning to forms:

    I : Obj(C) -> X

If two paths

    gamma : S -> T
    delta : S -> T

have the same endpoint `T`, their final state interpretation is the same
object/value `I(T)`.

This is endpoint-state independence.

It does not imply that `gamma` and `delta` are equal paths or that their
path-level interpretations are equal.

## 3. Compositional path interpretation

A compositional PETRA path interpretation is represented by a functor

    F : C -> D

into a target category `D`.

Therefore:

    F(delta o gamma) = F(delta) o F(gamma)

for composable paths, and

    F(id_S) = id_{F(S)}.

Composition preservation and empty-path identity are therefore functorial
laws, not properties of every arbitrary PETRA interpretation.

## 4. Road inheritance

PETRA path interpretation does not create structural roads.

The source category `C` is determined by the ASHES elementary edit structure.

An interpretation may assign mathematical meaning to existing forms and
paths, but it cannot create, remove, legalize, or forbid ASHES edits.

## 5. Inverse cancellation

In the free path category, an ADD edge followed by its reversing REMOVE edge
is a length-two path, not an identity.

Let `C_inv` be the quotient of `C` by the elementary inverse-cancellation
congruence.

`C_inv` is a groupoid.

A path interpretation preserves elementary ADD/REMOVE cancellation exactly
when it factors through the relevant inverse-cancellation quotient:

    C -> C_inv -> D

Thus inverse-effect preservation is an additional property of a path
interpretation, not a consequence of arbitrary state interpretation alone.

### Proposition — inverse-cancellation factorization

Let

    q : C -> C_inv

be the quotient functor.

For every compositional path interpretation

    F : C -> D,

the following are equivalent:

1. `F` maps every elementary ADD/reversing-REMOVE pair to the corresponding
   identity in `D`;
2. `F` is constant on `≡_inv` equivalence classes;
3. there exists a unique functor

       F_bar : C_inv -> D

   such that

       F = F_bar o q.

Proof.

If `F = F_bar o q`, every elementary inverse pair is identified with an
identity by `q`, so its image under `F` is also an identity.

Conversely, if `F` sends every generating inverse-cancellation relation to
equality in `D`, functoriality makes `F` invariant under composition with
those relations on either side. Therefore `F` is constant on the least path
congruence generated by them, namely `≡_inv`, and so factors uniquely through
the quotient `C_inv`.

QED.

## 6. Closed paths

A non-empty closed path

    gamma : S -> S

has the same source and target form as `id_S`, but need not equal the empty
path.

Therefore PETRA may distinguish:

- final-state semantics, for which both terminate at `I(S)`;
- path observables, which may distinguish `gamma` from `id_S`.

### Proposition — closed-path nontriviality

There exist non-empty closed paths

    gamma : S -> S

that are distinct from `id_S` in the free path category `C`.

For any witnessed elementary edit

    a : S -> T

with reversing edit

    a_inv : T -> S,

the composite

    gamma = a_inv o a

has source and target `S` but has path length two.

Since `C` is free before additional path relations are imposed,

    gamma != id_S.

Thus equal endpoints do not imply path equality.

### Interpretation consequence

For a compositional path interpretation

    F : C -> D,

whether a closed path remains observable depends on which path relations `F`
identifies.

If `F` factors through `C_inv`, an elementary inverse loop satisfies

    F(a_inv o a) = F(id_S).

An interpretation that does not impose that cancellation may distinguish the
same closed path from `id_S`.

Therefore closed-path nontriviality is structural, while closed-path
observability is interpretation-dependent.

## 7. Path observables

A PETRA interpretation may study observables attached to paths without making
them part of ASHES form identity.

Examples include:

- path length;
- ADD count;
- REMOVE count;
- duration;
- temporal ordering;
- recurrence;
- cycle properties.

Temporal information is therefore treated as possible path information, not
as a new ASHES structural dimension and not as a separate PETRA theory.

### Proposition — observable quotient criterion

Let `O` be a path observable.

For parallel paths `gamma` and `delta`, define

    gamma ~_O delta

exactly when

    O(gamma) = O(delta).

This is an equivalence relation on each parallel-path set.

The observable-induced equivalence supports a quotient category of paths
exactly when it is a path congruence: whenever

    gamma ~_O delta,

every defined common prefix and suffix preserve equivalence,

    alpha o gamma o beta ~_O alpha o delta o beta.

When this condition holds, `O` is constant on the quotient classes and may
factor through the corresponding path quotient.

When it fails, `O` remains a valid path observable but does not by itself
define a compositional quotient semantics.

Thus observational indistinguishability and compositional path equivalence
are distinct notions.

### Additive observables

Any path observable with values in a monoid and satisfying

    O(delta o gamma) = O(delta) + O(gamma)

has a composition-stable equality kernel on parallel paths.

Examples to investigate include:

- path length;
- ADD count;
- REMOVE count;
- duration, only if an explicit additive temporal law is adopted.

No additive law for temporal duration is assumed by this note.

### Proposition — edit-count homomorphism

For every finite witnessed edit path `gamma`, define

    C(gamma) = (A(gamma), R(gamma))

where `A(gamma)` is the number of ADD edges and `R(gamma)` is the number of
REMOVE edges.

Then

    C(delta o gamma) = C(delta) + C(gamma)

componentwise for every pair of composable paths.

Therefore `C` is an additive path observable with values in the commutative
monoid `N x N`.

As an immediate consequence,

    length(gamma) = A(gamma) + R(gamma)

is also additive.

Hence equality of edit-count vectors and equality of path lengths each induce
composition-stable equivalence relations on parallel paths.

### Proposition — net edit balance

Let

    gamma : S -> T

be any finite witnessed edit path.

Every ADD edge increases intrinsic ASHES size by one, and every REMOVE edge
decreases intrinsic ASHES size by one.

Therefore

    size(T) - size(S) = A(gamma) - R(gamma).

Define the balance observable

    B(gamma) = A(gamma) - R(gamma).

Then

    B(gamma) = size(target(gamma)) - size(source(gamma)).

Hence `B` depends only on the endpoints of the path.

It is also additive:

    B(delta o gamma) = B(delta) + B(gamma)

for every pair of composable paths.

### Corollary — closed-path balance

For every closed path

    gamma : S -> S,

we have

    A(gamma) = R(gamma).

Thus every closed PETRA edit path has zero net edit balance, even when the
path itself is non-empty and structurally non-trivial.

### Corollary — closed-path parity

For every closed path

    gamma : S -> S,

the net-balance theorem gives

    A(gamma) = R(gamma).

Therefore

    length(gamma)
        = A(gamma) + R(gamma)
        = 2 * A(gamma)
        = 2 * R(gamma).

Hence every closed PETRA edit path has even length.

In particular, every non-empty closed path has length at least two.

### Proposition — edit-word composition law

Let the edit alphabet be

    Sigma = {A, R},

where `A` denotes an ADD edge and `R` denotes a REMOVE edge.

For every finite witnessed edit path

    gamma = e_1 ... e_n,

define its edit word

    W(gamma) in Sigma*

by replacing every ADD edge with `A` and every REMOVE edge with `R`.

The empty path has the empty word.

Using the categorical convention that

    delta o gamma

means first `gamma` and then `delta`, path composition satisfies

    W(delta o gamma) = W(gamma) W(delta),

where juxtaposition denotes ordinary left-to-right word concatenation.

Thus the edit word preserves the temporal/order sequence of elementary edit
types along a path.

The edit-count observable is obtained from `W` by forgetting order and counting
the occurrences of `A` and `R`.

The balance observable is obtained by sending

    A -> +1
    R -> -1.

Path length is the word length of `W(gamma)`.

Thus the previously defined edit-count, balance, and length observables are
coarser projections of the edit-word observable.

### Corollary — closed-path words are balanced

If

    gamma : S -> S,

then `W(gamma)` contains equally many `A` and `R` symbols.

This does not imply that two closed paths with the same counts have the same
edit word or the same structural path.

### Proposition — edit-word non-faithfulness

The edit-word observable does not determine a witnessed structural path.

There exist a PETRA form `P` and two witnessed ADD edits

    a : P -> Q_1
    b : P -> Q_2

with non-isomorphic target forms

    Q_1 != Q_2.

The two paths are therefore distinct, while

    W(a) = A = W(b).

Hence equality of edit words does not imply equality of witnessed paths.

The edit word forgets at least:

- the selected structural target witness;
- the intermediate PETRA forms;
- the structural location at which an elementary edit acts.

Thus `W` preserves the ordered sequence of edit types but is not faithful to
the full witnessed path structure.

### Theorem — primitive edit lifting

Let

    F : C -> D

be a compositional PETRA path interpretation.

For every witnessed elementary ASHES edit

    e : S -> T

where `e` is either ADD or REMOVE, there is an induced target transformation

    F(e) : F(S) -> F(T).

The existence and legality of `e` are determined entirely by ASHES.

PETRA does not create, remove, legalize, or forbid the edit. It assigns
mathematical interpretation to the already-existing source form, target form,
and edit path.

For composable elementary edits

    a : S -> T
    b : T -> U,

functoriality gives

    F(b o a) = F(b) o F(a).

Therefore finite ASHES ADD/REMOVE computations lift coherently to PETRA
transformations.

No inverse law is implied by this theorem alone. Inverse-effect preservation
requires the additional factorization condition established for H3.

### Primitive ADD/REMOVE semantics

Let

    S = Node(M)

and let `T` be a child-form class involved in one elementary ADD or REMOVE.

PETRA interprets the resulting ASHES form using

    I(Node(M))
        =
    product over U in supp(M) of
        A(M,U) ^ E(mult_M(U), I(U)).

This gives four elementary structural cases.

#### ADD — existing child-form class

If `T` is already in `supp(M)`, ADD increases its multiplicity by one.

The support is unchanged, while the multiplicity input for `T` changes from

    m

to

    m + 1.

The resulting PETRA interpretation is recomputed from the new multiset.

#### ADD — new child-form class

If `T` is not in `supp(M)`, ADD introduces `T` into the support with
multiplicity one.

The resulting PETRA interpretation therefore contains a prime-powered factor
associated with the newly present child-form class `T`, subject to the selected
prime-assignment and exponent policies.

#### REMOVE — duplicate child-form class

If `T` has multiplicity greater than one, REMOVE decreases its multiplicity by
one while `T` remains in the support.

The resulting PETRA interpretation is recomputed using the decreased
multiplicity.

#### REMOVE — last occurrence of a child-form class

If `T` has multiplicity one, removing that occurrence removes `T` from the
support.

The prime-powered factor associated with that child-form class is therefore
absent from the resulting PETRA product.

### Policy-dependence boundary

The base PETRA contract does not require

    A(M,T)

to remain unchanged when the surrounding child multiset `M` changes.

Therefore these four cases classify the guaranteed structural effect on PETRA
interpretation inputs. They do not claim that an existing prime assignment
remains numerically fixed across an edit.

A more specific interpretation policy may prove stronger arithmetic laws.

## 8. Current hypotheses

H1 — Endpoint-state independence
    Same endpoint form implies the same final state interpretation.

H2 — Road inheritance
    Structural edit legality is inherited from ASHES.

H3 — Inverse-effect preservation
    Requires factorization through inverse cancellation when demanded.

H4 — Empty-path identity
    Preserved by every compositional path interpretation.

H5 — Composition preservation
    Defines the compositional/functorial path-interpretation class.

H6 — Associativity
    Inherited from source and target categorical composition.

H7 — Closed-path distinction
    Equal endpoints do not imply equality of paths or path observables.

H8 — Observable quotient criterion
    An observable induces a compositional path quotient exactly when its
    equality kernel on parallel paths is a path congruence.

H9 — Edit-count homomorphism
    ADD count and REMOVE count form an additive `N x N` path observable.

H10 — Net edit balance
    For every path `gamma : S -> T`,
    `A(gamma) - R(gamma) = size(T) - size(S)`.

H11 — Closed-path parity
    Every closed path has even length; every non-empty closed path has length
    at least two.

H12 — Edit-word composition law
    Every path determines a word in `{A,R}*`; with categorical composition,
    `W(delta o gamma) = W(gamma) W(delta)`.

H13 — Edit-word non-faithfulness
    Equal edit words do not imply equal witnessed structural paths.

## 9. Boundary

This note does not identify arbitrary equal-endpoint paths.

It does not claim that every PETRA interpretation is compositional.

It does not make temporal observables intrinsic to ASHES forms.

ASHES remains unchanged.

## P2 — Two-step REMOVE/ADD composition

The first non-trivial composed PETRA path considered here is the two-step
SHAPES path

```text
gamma:
S --REMOVE--> M --ADD--> T
```

No new PETRA structural primitive is introduced.

Both arrows are inherited unchanged from the intrinsic SHAPES edit algebra.
PETRA interprets the resulting states and, when a path interpretation is
selected, the composed path.

Under the normative SHAPES contract:

- elementary `REMOVE` deletes one eligible zero-child non-root occurrence;
- elementary `ADD` creates one fresh zero-child occurrence.

Therefore this composition does not replace an arbitrary child form `U` with
an arbitrary child form `V`.

Writing

```text
Z := Node(empty multiset),
```

the first step removes one witnessed occurrence of `Z`, and the second step
adds one fresh occurrence of `Z`.

At the pointed-realization level, the parent selected by `REMOVE` and the
parent selected by the subsequent `ADD` need not be the same occurrence.

Consequently the composition has two elementary cases.

If `ADD` reconstructs the incidence removed by the preceding `REMOVE`, the
endpoint is structurally equal to the source:

```text
T = S.
```

Otherwise the fresh zero-child occurrence is attached at another legal target
and the endpoint may be structurally different:

```text
T != S.
```

The latter may be described informally as relocation of one terminal leaf,
but `RELOCATE` is not introduced as a PETRA or SHAPES primitive.

For every compositional PETRA path interpretation

```text
F : C -> D,
```

composition gives

```text
F(gamma)
=
F(ADD) o F(REMOVE).
```

This is inherited composition, not a new PETRA algebraic generator.

### P2.1 Endpoint interpretation

PETRA state interpretation remains the ordinary recursive rule

```text
I(Node(M))
=
product over X in supp(M) of
A(M,X) ^ E(mult_M(X), I(X)).
```

Thus the source and target are interpreted independently from their resulting
SHAPES forms:

```text
I(S)
```

and

```text
I(T).
```

The path used to reach `T` does not alter the state interpretation of `T`.

Therefore, by endpoint-state independence:

```text
T = S
=>
I(T) = I(S).
```

If instead:

```text
T != S,
```

no equality between `I(T)` and `I(S)` follows from the general PETRA
interpretation contract.

A non-empty closed path may still be distinguished from the empty path by a
path interpretation that observes path information.

## P3 — Universal laws of one REMOVE followed by one ADD

Let

```text
gamma:
S --REMOVE--> M --ADD--> T.
```

No additional hypothesis on the prime-assignment policy `A` or exponent policy
`E` is assumed.

### P3.1 Edit word

The edit word is

```text
W(gamma) = RA.
```

### P3.2 Edit counts

The path contains exactly one edit of each kind:

```text
A(gamma) = 1
R(gamma) = 1.
```

Hence:

```text
C(gamma) = (1,1).
```

### P3.3 Net edit balance

By the general edit-balance law:

```text
A(gamma) - R(gamma)
=
size(T) - size(S).
```

Therefore:

```text
1 - 1
=
size(T) - size(S),
```

and so:

```text
size(T) = size(S).
```

Every legal two-step `REMOVE ; ADD` composition therefore preserves SHAPES
size.

This is inherited structural information. It is not an arithmetic invariant
introduced by PETRA.

### P3.4 Closed inverse instance

When the second edit reconstructs the incidence removed by the first edit:

```text
T = S.
```

Endpoint-state independence then gives:

```text
I(T) = I(S).
```

Nevertheless:

```text
W(gamma) = RA
```

while the empty path has:

```text
W(id_S) = epsilon.
```

Thus the smallest inverse pair already exhibits:

```text
same endpoint
does not imply
same witnessed path.
```

### P3.5 No general multiplicative update law

No stronger arithmetic update formula follows for arbitrary admissible `A`
and `E`.

In particular, the general PETRA contract does not imply that a
`REMOVE ; ADD` composition:

- divides by one fixed prime-powered factor and multiplies by another;
- modifies only one exponent;
- modifies only one prime base;
- preserves divisibility;
- preserves numerical order;
- preserves the interpreted value when the endpoint form changes;
- has a multiplicative ratio `I(T) / I(S)` determined only by the two edited
  occurrences.

The first obstruction is that

```text
A(M,X)
```

may depend on the complete local child multiset `M`.

A local structural change may therefore reassign prime bases even for
child-form classes that remain present.

There is also a recursive obstruction.

When an edit occurs below the root, the interpreted value of the modified
subform may change. That value is an input to the exponent policy at its
parent, so the arithmetic effect may propagate through the ancestor chain.

At an affected ancestor, structural child-form classes may also merge or split
relative to siblings after the edit. Therefore neither factor locality nor
prime-base stability follows from PETRA in general.

The only universally valid state-level rule is:

```text
recompute I on the resulting SHAPES form
```

using the selected admissible policies `A` and `E`.

Any stronger arithmetic law requires additional stated properties of a
concrete interpretation policy and belongs to policy-specific PETRA theory.

## Boundary after P3

This note stops here.

The result established is deliberately narrow.

For every legal composition

```text
REMOVE ; ADD
```

we have universally:

```text
W = RA
C = (1,1)
size(target) = size(source).
```

For the closed inverse instance:

```text
target = source
=>
I(target) = I(source).
```

No stronger arithmetic law is claimed without additional hypotheses on `A`
and `E`.

In particular, this result does not:

- introduce a `REPLACE` primitive;
- introduce a `RELOCATE` primitive;
- modify SHAPES;
- promote this research note into the normative PETRA specification;
- specialize the result to LRPE;
- continue into additional path meta-theory.

## P4 — Local factor law under context-stable prime assignment

P3 established that arbitrary admissible PETRA policies do not support a
general local multiplicative update law.

The first stronger arithmetic law appears after imposing one additional
property on the prime-assignment policy.

### P4.1 Context-stable prime assignment

Call a prime-assignment policy context-stable when there exists a function

```text
a : S -> Primes
```

such that, whenever `X` occurs in the support of an admissible child multiset
`M`,

```text
A(M,X) = a(X).
```

Thus the prime assigned to a child-form class depends only on that SHAPES form,
not on the surrounding child multiset.

This is an additional PETRA policy property.

It is not required by the base PETRA contract.

No additional property of the exponent policy `E` is assumed here.

### P4.2 Parent-local interpretation form

Let

```text
P = Node(M).
```

Under context-stable prime assignment,

```text
I(P)
=
product over X in supp(M) of
a(X) ^ E(mult_M(X), I(X)).
```

Consider one elementary ASHES edit applied directly at the parent occurrence
represented by `P`.

Because elementary ADD and REMOVE operate on zero-child occurrences, write

```text
Z := Node(empty multiset)
```

with

```text
I(Z) = 1.
```

For every child-form class

```text
X != Z,
```

the direct edit leaves both

```text
mult_M(X)
```

and

```text
I(X)
```

unchanged.

Context stability also leaves its prime base

```text
a(X)
```

unchanged.

Therefore every factor associated with an unchanged child-form class is
identical before and after the direct edit.

The complete parent-local arithmetic effect is confined to the factor
associated with `Z`.

### P4.3 ADD when Z is already present

Suppose

```text
mult_M(Z) = m >= 1.
```

After one direct ADD at `P`, let

```text
P' = Node(M + [Z]).
```

Then

```text
mult_{M+[Z]}(Z) = m + 1.
```

All non-`Z` factors cancel in the quotient, so in the positive rationals:

```text
I(P') / I(P)
=
a(Z) ^
(
    E(m+1, 1) - E(m, 1)
).
```

Equivalently:

```text
I(P')
=
I(P)
*
a(Z) ^
(
    E(m+1, 1) - E(m, 1)
).
```

This signed-exponent identity is an exact arithmetic update law.

It does not imply divisibility because no monotonicity property of `E` has
been assumed.

### P4.4 ADD when Z is a new support class

Suppose

```text
Z not in supp(M).
```

After one direct ADD:

```text
P' = Node(M + [Z]).
```

The new class `Z` enters the support with multiplicity one.

Every pre-existing factor is unchanged, and therefore:

```text
I(P')
=
I(P) * a(Z) ^ E(1,1).
```

Hence:

```text
I(P') / I(P)
=
a(Z) ^ E(1,1).
```

In this case the ratio is a positive integer and the new local interpretation
contains exactly one additional prime-powered factor associated with `Z`.

This conclusion was not valid for arbitrary PETRA prime assignment because
changing `M` could previously reassign bases for already-present classes.

### P4.5 REMOVE when Z remains present

Suppose

```text
mult_M(Z) = m > 1.
```

After one direct REMOVE:

```text
P' = Node(M - [Z]).
```

Then

```text
mult_{M-[Z]}(Z) = m - 1.
```

Again all non-`Z` factors are unchanged, so in the positive rationals:

```text
I(P') / I(P)
=
a(Z) ^
(
    E(m-1, 1) - E(m, 1)
).
```

Equivalently:

```text
I(P')
=
I(P)
*
a(Z) ^
(
    E(m-1, 1) - E(m, 1)
).
```

No divisibility direction follows without an additional property of `E`.

### P4.6 REMOVE of the last Z occurrence

Suppose

```text
mult_M(Z) = 1.
```

After one direct REMOVE, `Z` leaves the support.

If

```text
P' = Node(M - [Z]),
```

then:

```text
I(P)
=
I(P') * a(Z) ^ E(1,1).
```

Equivalently:

```text
I(P') / I(P)
=
a(Z) ^ (-E(1,1))
```

in the positive rationals.

Thus removal of the last `Z` occurrence removes exactly the corresponding
prime-powered factor from the parent-local interpretation.

### P4.7 Theorem — local factor law

Let `I` be a PETRA interpretation whose prime-assignment policy is
context-stable:

```text
A(M,X) = a(X).
```

For any elementary ADD or REMOVE applied directly to a parent

```text
P = Node(M),
```

every prime-powered factor associated with a child-form class other than `Z`
is unchanged.

The arithmetic effect at that parent is exactly the change in the `Z` factor.

Therefore context-stable prime assignment is sufficient to upgrade the base
PETRA rule

```text
recompute the complete local product
```

to an exact parent-local factor update law.

### P4.8 Locality boundary

This theorem is local to the directly edited parent.

If `P` is itself a child of an ancestor, changing `I(P)` may alter the exponent
input used by that ancestor:

```text
E(mult(P), I(P)).
```

The resulting arithmetic effect may therefore propagate recursively toward
the root.

P4 does not imply that only one prime-powered factor changes in the
interpretation of the complete SHAPES form.

### P4.9 What P4 still does not prove

Context-stable prime assignment alone does not imply:

```text
ADD => I(P) divides I(P')
```

or:

```text
REMOVE => I(P') divides I(P).
```

It also does not imply numerical monotonicity.

Such conclusions require an additional property of `E`, for example an
appropriate monotonicity law in the multiplicity argument.

That stronger step is deliberately not taken here.

## Boundary after P4

The additional assumption introduced in P4 is exactly:

```text
A(M,X) = a(X).
```

Under that assumption PETRA gains an exact parent-local multiplicative update
law for elementary ADD and REMOVE.

No property of `E` beyond the base PETRA contract is introduced.

In particular, this tranche does not:

- assert divisibility;
- assert numerical monotonicity;
- specialize to LRPE;
- modify ASHES;
- modify the normative PETRA specification;
- introduce a new structural primitive;
- continue into a stronger P5 result.

## P5 — Local divisibility law

P4 established an exact parent-local factor law under context-stable prime
assignment:

```text
A(M,X) = a(X).
```

P5 adds one further property, restricted to exactly the exponent values
required by elementary ASHES leaf edits.

### P5.1 Leaf-multiplicity monotonicity

Call an exponent policy leaf-multiplicity monotone when:

```text
m1 <= m2
=>
E(m1,1) <= E(m2,1)
```

for every positive multiplicity pair on which the policy is defined.

Equivalently, the sequence

```text
E(1,1), E(2,1), E(3,1), ...
```

is nondecreasing.

This condition concerns only the second argument value

```text
v = I(Z) = 1.
```

It does not impose monotonicity of

```text
E(m,v)
```

for arbitrary interpreted child values `v`.

Thus P5 does not require a general monotonicity theorem for the complete
exponent policy.

### P5.2 Assumptions

Throughout P5 assume both:

```text
A(M,X) = a(X)
```

and:

```text
m1 <= m2
=>
E(m1,1) <= E(m2,1).
```

The first is the context-stability property from P4.

The second is leaf-multiplicity monotonicity.

No other property of `A` or `E` is introduced.

### P5.3 ADD when Z is already present

Let

```text
P = Node(M)
```

with:

```text
mult_M(Z) = m >= 1.
```

After one direct ADD:

```text
P' = Node(M + [Z]).
```

By P4:

```text
I(P') / I(P)
=
a(Z) ^
(
    E(m+1,1) - E(m,1)
).
```

Leaf-multiplicity monotonicity gives:

```text
E(m+1,1) - E(m,1) >= 0.
```

Therefore the quotient is a positive integer:

```text
I(P') / I(P) in N+.
```

Hence:

```text
I(P) divides I(P').
```

### P5.4 ADD when Z is a new support class

If:

```text
Z not in supp(M),
```

P4 gives:

```text
I(P')
=
I(P) * a(Z)^E(1,1).
```

Because the base PETRA exponent contract has:

```text
E(1,1) in N+,
```

the multiplier is a positive integer.

Therefore:

```text
I(P) divides I(P').
```

No additional monotonicity argument is required for this boundary case.

### P5.5 REMOVE when Z remains present

Let:

```text
mult_M(Z) = m > 1.
```

After one direct REMOVE:

```text
P' = Node(M - [Z]).
```

P4 gives:

```text
I(P') / I(P)
=
a(Z) ^
(
    E(m-1,1) - E(m,1)
).
```

Leaf-multiplicity monotonicity gives:

```text
E(m-1,1) <= E(m,1).
```

Equivalently:

```text
I(P) / I(P')
=
a(Z) ^
(
    E(m,1) - E(m-1,1)
)
```

with non-negative exponent.

Therefore:

```text
I(P') divides I(P).
```

### P5.6 REMOVE of the last Z occurrence

If:

```text
mult_M(Z) = 1,
```

P4 gives:

```text
I(P)
=
I(P') * a(Z)^E(1,1).
```

Therefore directly:

```text
I(P') divides I(P).
```

Again, no additional monotonicity argument is required for this boundary case.

### P5.7 Theorem — local divisibility orientation

Let a PETRA interpretation satisfy:

```text
A(M,X) = a(X)
```

and let its exponent policy be leaf-multiplicity monotone:

```text
m1 <= m2
=>
E(m1,1) <= E(m2,1).
```

For every elementary ADD applied directly to a parent:

```text
P --ADD--> P',
```

we have:

```text
I(P) divides I(P').
```

For every elementary REMOVE applied directly to a parent:

```text
P --REMOVE--> P',
```

we have:

```text
I(P') divides I(P).
```

Thus direct elementary leaf addition is locally divisibility-increasing, while
direct elementary leaf removal is locally divisibility-decreasing.

This is a conditional PETRA arithmetic law.

It is not a SHAPES structural law.

### P5.8 Corollary — local numerical monotonicity

PETRA state values lie in the positive integers.

For positive integers:

```text
x divides y
=>
x <= y.
```

Therefore P5 implies:

```text
P --ADD--> P'
=>
I(P) <= I(P')
```

and:

```text
P --REMOVE--> P'
=>
I(P') <= I(P).
```

So direct ADD is locally nondecreasing in PETRA value and direct REMOVE is
locally nonincreasing.

The inequalities need not be strict.

If, for example,

```text
E(m+1,1) = E(m,1),
```

then an ADD to an already-present `Z` class may leave the parent-local PETRA
value unchanged.

Strict numerical growth would require a stronger assumption such as:

```text
E(m+1,1) > E(m,1).
```

No such stronger assumption is introduced here.

### P5.9 Locality boundary

P5 inherits the locality boundary of P4.

The theorem concerns the interpretation of the parent directly edited by the
elementary ADD or REMOVE.

If that parent occurs below an ancestor, the changed value

```text
I(P)
```

becomes an input to an ancestor exponent:

```text
E(mult(P), I(P)).
```

P5 imposes no monotonicity condition on the second argument of `E`.

Therefore P5 does not imply:

```text
deep ADD
=>
root interpretation increases
```

or:

```text
deep REMOVE
=>
root interpretation decreases.
```

Nor does it establish a global divisibility relation between the complete
source and target interpretations for an arbitrary deep edit.

Those claims would require additional assumptions involving the `v` argument
of `E` and are outside this result.

---

## Boundary after P5

P5 adds exactly one property beyond P4:

```text
m1 <= m2
=>
E(m1,1) <= E(m2,1).
```

Together with context-stable prime assignment:

```text
A(M,X) = a(X),
```

this proves the parent-local divisibility laws:

```text
ADD:
I(before) divides I(after)

REMOVE:
I(after) divides I(before).
```

Local numerical monotonicity follows as a corollary.

This tranche does not:

- require strict monotonicity;
- impose monotonicity in the second argument of `E`;
- derive root-level monotonicity for deep edits;
- derive global divisibility for arbitrary deep edits;
- specialize to LRPE;
- modify ASHES;
- modify the normative PETRA specification;
- continue to a P6 result.
